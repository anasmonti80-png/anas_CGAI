# ADR-0001 — أساس معماري محلي قائم على الأدلة

- **الحالة:** Accepted
- **التاريخ:** 2026-11-12
- **المالك:** فريق CyberGuard AI
- **المتطلبات المرتبطة:** CG-001..CG-1440، وبالأخص CG-1417..CG-1440

## السياق

السجل يحوي 1,440 متطلبًا تاريخيًا متداخلًا. لا يوجد دليل تشغيل أو اختبارات منصات أو موصلات حية عند اتخاذ هذا القرار. يلزم تجنب منصة ظاهرها مكتمل لكنها تخلط بين دليل الأصل، حالة الحماية، وادعاء المنع أو الاستجابة.

## القرار

يبنى المنتج على مراحل محلية أولًا، حول سجل أدلة غير قابل للخلط: كل حدث وأصل وتنبيه وإجراء يحمل مصدره ووقته ومستوى ثقته وحالة التحقق. تُفصل طبقات الواجهة، التطبيع، قواعد الكشف، محرك السياسات/الموافقة، وموصلات المصادر. لا تنفذ واجهة AI أو موصلات السحابة أو NCC إجراءً مباشرًا؛ تمر كل عملية مؤثرة عبر عقد typed، نطاق مصرح، معاينة، موافقة مستقلة، تحقق بعد التنفيذ، وتراجع عند الإمكان.

CyberGuard يملك سياق الأمن والتحقيقات، بينما تظل إدارة الشبكة التنفيذية لدى NCC، والمحاكاة لدى IT Twin، وITSM لدى Tickets. تبدأ الموصلات بوضع read-only وتعلن `Unknown` أو `Unsupported` عند غياب الدليل.

## البدائل والعواقب

- **لوحة موحّدة مع أرقام افتراضية:** مرفوضة لأنها توحي بتغطية وحماية بلا دليل.
- **موصلات مباشرة ذات صلاحيات واسعة:** مرفوضة قبل مختبر مصرح ومصفوفة صلاحيات وموافقات.
- **منصة مركزية سحابية أولًا:** مؤجلة؛ الافتراضي المحلي يحد من خروج البيانات، مع عقد صريح لأي egress لاحق.

ينتج عن القرار أن التقدم يقاس بالاختبارات والأدلة لكل منصة وموصل، لا بعدد الشاشات. يلزم قبل إعلان أي قدرة: رابط متطلب → مكوّن → اختبار → نتيجة → إصدار، مع توثيق القيود.
