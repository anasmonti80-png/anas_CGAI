المطلوب النهائي جميع المتطلبات ضمن نطاق V3. هذه الخطة لا تختصر النطاق إلى المرحلة الأولى. لا يعلن اكتمال النظام بمجرد اكتمال الأساس.

| المرحلة | المخرجات | بوابة القبول |
|---|---|---|

## المخاطر والعوائق

| الرمز | الخطر أو الاعتماد | الإجراء |
|---|---|---|
| R01 | 1,440 سجلًا تاريخيًا متداخلًا | حفظ النص؛ تصنيف آلي أولي؛ مراجعة كل قرار نقل/تكرار قبل تنفيذه |
| R02 | لا عينات أو حسابات موصلات مؤسسية | استيراد عقد موثق؛ اختبارات اصطناعية موسومة؛ لا ادعاء تكامل حي |
| R03 | لا macOS/Linux lab حاليًا | مسارات CI منفصلة؛ دعم Not Tested إلى توفر نتيجة فعلية |
| R04 | لا ترخيص EDR/Apple entitlement | لا تثبيت AV أو تجاوز صلاحيات؛ عقد قدرات فقط |
| R05 | قاعدة SQLite واحدة / مزامنة عمليات | قياس 5,000 أصل للتصفح؛ لا تعميم النتيجة إلى ingest أو 20,000 أصل |
| R06 | تدقيق محلي يمكن إعادة كتابته بصلاحية OS | سلسلة بصمات تكشف تعديلًا جزئيًا؛ تثبيت خارجي/WORM لاحقًا |
| R07 | المرجع البصري لا يحدد حالات البيانات المفقودة | استُلمت الصورة وطابقت بصمتها الأصل؛ التصميم يتبعها مع حالات Unknown بدل أرقام وهمية |
| R08 | متطلبات سيادة وتشريعات تعتمد على الجهة | Not Assessed؛ لا شهادة امتثال دون مراجعة العميل |
| R09 | لا بنية توقيع/توزيع وتحديث مؤسسية | منع وصف preview بأنه production-ready |
| R10 | HTTP محلي ومصادقة داخلية محدودة | loopback فقط؛ لا نفق/إتاحة LAN قبل التحقق الأمني |

## منهج الاختبارات

`node --test tests/*.test.js` بعد كل مرحلة مادية. اختبارات وحدة وخادم HTTP حقيقي على loopback بقاعدة مؤقتة وبيانات اصطناعية، فشل ومصادقة/صلاحيات وOrigin وحدود وحفظ بيانات. قياس صفحات 5,000 أصل لا يحاكي حساسات حقيقية. اختبارات المتصفح تتحقق RTL/LTR وأحجام الشاشة وسلوك النموذج. Windows المحلي فقط يُسجل بيئة التنفيذ الحالية. لا تُسجل بيئة CI أو منصة أخرى كناجحة قبل تشغيلها.

Unit Tested = اختبارات منطق/تكامل محلية ببيانات اختبار؛ Lab Tested = موصل/جهاز حقيقي في مختبر مصرح؛ Production Validated = دليل إنتاج مستقل. لا انتقال للحالة بالافتراض.

## حالة التنفيذ — 2026-11-12 بتوقيت الرياض

M0: حفظ وتحقق آلي لكل المصادر، وتصنيف مبدئي لـ1,440 متطلبًا، ومراجعة دلالية نطاقية لـCG-001 إلى CG-600، إضافة إلى مراجعات حدود مباشرة لـ33 سجلًا. المراجعة الدلالية لبقية السجل وبوابات القبول ما زالت مطلوبة.

M1–M3: توجد أجزاء تشغيلية واختبارات للهوية والأدلة وواجهة SOC والتحقيقات والموافقات المحلية. CG-001..CG-005 وCG-007 وCG-008 وCG-016 وCG-022 وCG-032 وCG-054 وCG-056 وCG-057 وCG-061 وCG-068..CG-071 وCG-073 وCG-075..CG-082 اجتازت بواباتها المحددة؛ لا يترتب على ذلك اكتمال المراحل أو بقية المتطلبات. دورة الإجراء تعرض المحاكاة حتى التراجع، وصحة المصادر تميز Agent عن Log Forwarder، والوصول البعيد يميز الوجود عن الاتصال والتقييم. تعرض شاشة الهوية تدقيق AD/Entra للامتيازات وتغييرات Domain Admins والحسابات الخدمية والثقة وسياسات الدخول، وتعرض شاشة السياسات وظائف NIST الست ونموذج تهديد لكل بيئة، وتعرض التقارير سجل المخاطر ومصفوفة توافق الأنظمة القديمة وضوابط التعويض حتى الترحيل وأمان النسخ وجاهزية الاستعادة بقياسات RPO/RTO وسير تعافي الحوادث حتى إعادة الاتصال وضوابط مرونة إعدادات الشبكة ومسارات الإدارة وPlaybook انقطاع SOC وFail-safe السياسات المؤقتة، ويربط سجل الأصل المركزي سياق الحوكمة ودورة حياة المنتج والنظام ونهاية الدعم والتحديثات وخطة الترقية بدليله. يعرض سجل الفجوات الكيانات المعروفة وسبب غياب الرؤية. أضيفت أيضًا أوضاع التشغيل وعقد اكتشاف مصرح يفصل الواجهات المادية عن خدمات TCP/UDP. ومن M4 يوجد محوّل Windows Security بعينات اصطناعية؛ لا يدعي أي منهما موصل AD/Entra حيًا أو سجل Windows حيًا.

التالي: إكمال مراجعة متطلبات الموصلات وقواعد الكشف، عينات مخبرية مصرح بها لـWindows/Defender/Sysmon، توثيق ربط الهوية والثقة عبر المصادر، ثم تكاملات NCC/النموذج المحلي وسياسة الأدوات. تبقى حماية macOS/Linux والسحابة وDevSecOps والتعافي والاختبارات الدفاعية ضمن الخطة؛ لا يُحذف شيء من السجل التاريخي. الأفكار الجديدة تسجل في سجل قرارات منفصل وتربط بالمعرفات الأصلية؛ لا تغير النصوص أو تضخم نسبة الإنجاز.
