# بحث CG-176: تغطية محاكاة سياسات الشبكة

تاريخ المراجعة: 2026-11-27.

## السؤال

ما الذي تثبته محاكاة «ماذا لو» لقواعد الجدار الناري في CyberGuard (من CG-020)؟ وما الذي لا تثبته؟ ومتى يصح الاعتماد على نتيجتها في شبكة إنتاج حساسة؟

## المرجع: Batfish

- **الموردون:** يدعم Batfish إعدادات أجهزة من موردين كثيرين، منهم:
  - Cisco: ‏ASA وIOS وIOS-XE وIOS-XR وNX-OS.
  - Juniper (كل منصات JunOS) وPalo Alto وFortinet وArista وCheck Point وF5.
  - iptables، وبنى AWS (مجموعات الأمان وNACL وبوابات NAT وVPC).
  - ودعمه محدود لـ Aruba وDell Force10 وFoundry.
- **تحليل التمرير والوصول:**
  - تتبع المسار (traceroute) اتجاهي، ونسخته ثنائية الاتجاه.
  - بحث الوصول (reachability) عبر كل التدفقات المطابقة، ويعطي أمثلة لها.
  - كشف الحلقات، واتساق المسارات المتعددة.
  - نتائجه: قُبل، أو سُلّم إلى الشبكة الفرعية، أو رُفض، أو لا مسار. ويُذكر عند كل قفزة المرشح الذي سمح أو رفض.
- **الخلاصة:** هذا تحليل للشبكة كلها عبر أجهزة متعددة.

## نطاق محاكاة CyberGuard

| يُنمذج | لا يُنمذج |
|---|---|
| جهاز واحد: مرشحات الطبقتين الثالثة والرابعة بترتيب first-match أو deny-overrides | الترجمة (NAT) |
| احتواء نطاقات IPv4، وبادئات IPv6 بمقارنة حرفية | التوجيه والمسار عبر أجهزة أخرى |
| TCP وUDP وICMP وany، ونطاقات المنافذ | حركة العودة وحالة الجلسة |
| أسماء التطبيقات كتسميات مطابقة فقط | الجداول الزمنية، وقواعد المستخدم والهوية |
| موردو مجموعة القواعد (Palo Alto وFortiGate وCisco ASA/FMC وJuniper SRX وiptables/nftables وpfSense/OPNsense وMikroTik ومجموعات أمان السحابة) | فحص URL والمحتوى والطبقة السابعة (ومنها Cloud Armor) |
| | القواعد الضمنية للمورد غير الموجودة في التصدير، والكائنات المسماة غير المحلولة |

**مخرجات الوصول:** قرار قبل التغيير وبعده لتدفق عيّني واحد عند كل حافة قاعدة. هي ليست بحثًا شاملًا ولا تحليلًا من طرف إلى طرف.

## القرار

1. **تعلن كل محاكاة تغطيتها:**
   - `coverage`: النطاق والموردون والبروتوكولات وما لا يُنمذج ومعنى مخرجات الوصول.
   - `qualified` و`reasons`.
2. **أسباب عدم التأهيل:**
   - مورد غير منمذج.
   - كائنات مسماة غير محلولة.
   - بروتوكول غير منمذج.
   - قواعد تطبيقات.
   - قيود نطاق.
   - بادئات IPv6.
3. **التطبيق على شبكة إنتاج حساسة:**
   - جهاز الفلترة الحساس جدار ناري أو موجه، أو جهاز له مجموعة قواعد، وأهميته «حرجة» أو يخدم خدمة أعمال حرجة.
   - لا يُنفذ عليه إجراء مرشح شبكي (حظر أو سماح لعنوان أو منفذ) إلا بمحاكاة **مؤهلة** للجهاز نفسه من آخر 24 ساعة.
   - النتيجة غير المؤهلة أو القديمة لا تُطبق أبدًا.
4. **ما يتجاوز جهازًا واحدًا** (الترجمة والمسار وعدة أجهزة) يحتاج أداة تحليل شبكة كاملة مثل Batfish. ولا يدّعي CyberGuard تغطيته.
