# تشغيل CyberGuard AI — إصدار هندسي 0.1.0

هذه نسخة تشغيل محلية للوظائف المدرجة هنا، وليست اكتمال منصة الحماية ذات 1,440 متطلبًا. لا توجد كلمة مرور افتراضية ولا بيانات عرض داخل قاعدة التشغيل.

## التشغيل الأول

1. يلزم Node.js 24.21.0 أو إصدار تصحيحي أحدث ضمن 24. لا يلزم `npm install`؛ لا توجد تبعيات تشغيل npm.
2. شغّل `START_CYBERGUARD.cmd` على Windows، أو نفّذ `node scripts/launch.js` من مجلد المشروع.
3. افتح `http://127.0.0.1:4310` على الجهاز نفسه. لا تعرضه عبر tunnel أو reverse proxy؛ النسخة الحالية تقبل loopback فقط.
4. اقرأ ملف `data/setup-token` محليًا وأدخل الرمز في شاشة التهيئة. لا ترسله في محادثة أو تحفظه في لقطة شاشة. اختر اسم مسؤول وكلمة مرور لا تقل عن 14 حرفًا. يُحذف الملف بعد إنشاء أول مسؤول.
5. سجّل الدخول. إنشاء حساب ثانٍ بدور مسؤول يسمح بمراجعة طلبات الموافقات بصورة مستقلة؛ دور المحلل يراجع التنبيهات والتحقيقات، والمشاهد للقراءة فقط.

لا تُفتح نافذة متصفح تلقائيًا ولا يوجد اتصال بخدمة سحابية. `CG_PORT` يغير المنفذ المحلي، و`CG_DATA_DIR` يغير مجلد البيانات. حافظ على المجلد في حساب Windows الخاص بالمشغل وبصلاحيات وصول محدودة. تشفير القرص ونسخ البيانات مسؤولية التشغيل الحالية؛ SQLite ليست مشفرة بواسطة التطبيق.

## إضافة بيانات حقيقية مصرح بها

من «مصادر البيانات» أنشئ مصدرًا، ثم استورد ملف JSON وفق [عقد الأحداث](TELEMETRY_AR.md). المفتاح المستقل يظهر في حقل مخفي مرة واحدة؛ لا تضعه في ملف مواصفات أو command history. يمكن إبطاله أو تدويره من الواجهة. لا يرسل النظام ملفاتك إلى خارج الجهاز.

«جرد هذا الجهاز» عملية صريحة للقراءة فقط: اسم المضيف، عائلة النظام وعناوين الواجهات. لا تجمع المستخدمين أو كلمات المرور أو محتويات الملفات، ولا تفحص الشبكة أو تستنتج نجاح الحماية. تغيير اسم المضيف قد ينتج هوية جديدة؛ لا يعد ذلك محرك ربط هوية كاملًا.

عينات التنزيل و`node scripts/ui-lab.js` **اصطناعية فقط**. المختبر على المنفذ 4311 وبقاعدة مؤقتة، ولا يضيف بيانات إلى التشغيل الحقيقي. لا يُستخدم كخدمة دائمة.

## مسارات العمل المتاحة

- الأصل ← آخر أحداثه وبصماته ← تقرير أدلة JSON محلي حتمي، لا تقرير LLM.
- التنبيه ← إقرار بشري ← فتح تحقيق ← ملاحظات وحالة التحقيق. الإقرار لا يغلق التحقيق تلقائيًا ولا يثبت وصول رسالة SMS/Email.
- الأصل ← معاينة تغيير الأهمية ← موافقة مسؤول آخر ← تنفيذ محلي والتحقق ← تراجع إذا لم تتغير النسخة. لا منفذ جهاز أو firewall أو NCC في هذه النسخة.
- المصدر المتوقف يظهر «فقدان الرؤية» وينتج تنبيه صحة مستقلًا. وصول أحداث قديمة يثبت قناة الاستقبال فقط، ولا يثبت حداثة كل دليل.
- سجل التدقيق ← فحص التسلسل. السلسلة محلية ولا توفر WORM أو حماية من مدير نظام يعيد كتابة قاعدة البيانات كاملة.
- تغطية المتطلبات ← النصوص الأصلية والتصنيف الأولي. العدد 1,440 هو جرد المتطلبات؛ `Verified = 0` يعني أن قبولها الكامل عبر منصاتها لم يثبت بعد.

## إيقاف وحفظ واستعادة قاعدة التشغيل

أوقف الخادم بـCtrl+C وانتظر خروجه قبل نسخ مجلد `data` كاملًا إلى مخزن خاص مشفر. لا تنسخ DB منفردة أثناء التشغيل؛ ملفات WAL قد تحتوي معاملات أحدث. لاستعادة نسخة: أوقف الخدمة، احتفظ بنسخة المجلد الحالي، واستعد المجلد الخاص كاملًا ثم أعد التشغيل وفحص سلسلة التدقيق. هذه إجراءات حفظ قاعدة التطبيق فقط؛ ليست اختبارات استعادة Windows/AD أو دليل RTO/RPO للمؤسسة.

لا توجد أداة استرداد كلمة مرور أو MFA في هذا الإصدار؛ يجب حفظ حسابات المسؤولين في مدير كلمات مرور. لا تعدّل hashes أو قاعدة البيانات يدويًا. لا توجد مهمة تحديث أو تثبيت خدمة Windows أو نشر شبكة تلقائية.

## فحص الإصدار

`node scripts/verify.js` يفحص سلامة المواصفات والصياغة ويشغّل مجموعة الاختبارات، ويحفظ النتائج في `artifacts/verification.json` و`artifacts/tests.tap`. اختبارات الخادم تستخدم قواعد مؤقتة وأحداثًا اصطناعية ولا تُجري فحص شبكة.

راجع [المراحل والعوائق](engineering/MILESTONES_AR.md) و[سجل التحقق](engineering/VALIDATION_AR.md) قبل أي ادعاء تشغيل إنتاجي.
